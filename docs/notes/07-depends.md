# 07. Depends（依存性注入）の基礎

## 学んだこと
- `Depends` を使うことで、共通の事前処理や入力チェックをルート関数から引き剥がして再利用できる。
- **関数依存**: 通常の関数を渡して辞書などを返せる。
- **クラス依存**: クラスを渡すとオブジェクトとして受け取れるため、エディタで `params.limit` のように型補完が効く。型注釈と一致していれば `Depends()` と省略可能。
- **yield を使う依存**: `yield` の前がリクエスト処理前、`yield` の後がレスポンス返却後の後片付け（DBセッションのクローズ等）として自動実行される。
- **キャッシュ**: 1回のリクエスト内で同じ依存関係が複数回現れても、結果がキャッシュされて使い回される。

## Q&A（よくある質問と回答）

### Q1. Query や Path との関係は？
- **A**: 第03章で学んだ `Query` や `Path` の検証ルールを、`deps.py` の関数/クラス内に定義して `Depends` に渡すことで、複数のエンドポイントで1行で再利用できる部品として発展させたものです。

### Q2. 依存関数はアプリ作成時に実行されて登録されるのか？
- **A**: アプリ作成（起動）時には「どの関数をどう呼ぶか」という依存関係の解析・メタデータ登録が行われます。依存関数自体の実際の実行は「HTTPリクエストが届いたタイミング」です。ただし1回のリクエストの中で同じ依存が複数回現れた場合は、実行は最初の1回だけで、以降はその結果が使い回されます（キャッシュの寿命は1リクエスト）。

### Q3. `Depends()` と引数を空にする書き方は？
- **A**: `Annotated[CommonQueryParams, Depends()]` のように、型注釈に指定したクラス/型と `Depends` に渡す型が一致している場合、FastAPI が自動推論するため `Depends()` と省略できます（本来は `Depends(CommonQueryParams)`）。

### Q4. Depends に渡せるオブジェクトの種類は？
- **A**: Callable（呼び出し可能オブジェクト）であれば、通常関数・クラス・ジェネレータ関数のいずれも渡せます。ジェネレータ関数の場合は、`yield` の前後でリクエスト前後のライフサイクルを自動制御してくれます。

### Q5. deps.py に処理を切り出す主な理由は？
- **A**: 主に以下の2点です。
  1. **共通化と再利用**: ページネーションや認証チェックなど、複数APIで使い回す処理を1箇所にまとめられるため。
  2. **関心事の分離**: APIルート関数内に「DB接続のオープン/クローズ」などの前処理・後片付けロジックを書かずに済み、ルート関数を本質的な処理だけに集中させられるため。

### Q6. リクエスト由来のパラメータ（Path, Query, Body, Header）と Depends の役割の違いは？
- **A**: 
  - **`Path`, `Query`, `Body`, `Header`, `Cookie`**: HTTP リクエストの特定の位置から値を取り出し、バリデーション・型変換して注入するもの（**リクエスト由来のデータ抽出**）。
  - **`Depends`**: DB セッション、認証ロジック、外部 API クライアントなど、**アプリ内部のリソースや共通処理ロジック**を実行して注入するもの。
  - Pydantic モデル（`BaseModel` のサブクラス）を型注釈に指定した場合は、自動的にリクエストボディ（JSON）として解釈されます。

### Q7. Path, Query, Header 等と Pydantic のバリデーションの関係は？
- **A**: `Path`, `Query`, `Header`, `Cookie`, `Body` は、内部的に Pydantic の `FieldInfo`（`Field` の実体）を継承して作られています。
  そのため、引数名（または自動変換されたヘッダー名）でリクエストから値を抽出すると同時に、Pydantic の `ge`, `le`, `min_length`, `pattern` などのバリデーションルールがそのまま適用されます。

### Q8. エンドポイントではない依存関数（Dependsの先）で Header() や Query() を書いた場合、どうやって値が渡されるのか？
- **A**: 
  1. **依存グラフの構築**: FastAPI は起動時に、エンドポイントだけでなく `Depends` に渡された依存関数の中身も再帰的に走査（リフレクション）し、パラメータの依存関係ツリーを構築します。
  2. **リクエスト時の自動解決**: HTTP リクエストが届くと、FastAPI は内部の生リクエストから `Header` や `Query` の値を抽出し、Pydantic でバリデーションした上で、FastAPI 自身が依存関数（例: `get_current_user(x_api_key=...)`）を呼び出します。
  3. **戻り値の注入**: 実行された依存関数の戻り値が、エンドポイント関数の引数に注入されます。
  つまり、`Depends` で呼び出される関数は**エンドポイント関数と全く同じパラメータ解決ルールが使えるサブエンドポイント**のように機能します。

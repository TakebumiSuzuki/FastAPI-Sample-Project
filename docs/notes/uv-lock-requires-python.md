# requires-python と uv.lock の解決結果

## 1. `requires-python` は「範囲」を宣言する

`pyproject.toml` に書く `requires-python = ">=3.13"` は、1つのバージョンではなく**範囲**です。

```
requires-python = ">=3.13"
   ↓
3.13 でも 3.14 でも 3.15 でも動きます、という宣言
```

`uv.lock` の先頭にも同じ文字列がコピーされます。これは「この対応表を、どの範囲を前提に計算したか」の記録です。

```toml
# uv.lock の先頭
version = 1
revision = 3
requires-python = ">=3.13"
```

`pyproject.toml` 側を書き換えると、uvは前提が変わったと判断して `uv.lock` を作り直します。手で合わせる必要はありません。

---

## 2. 範囲を宣言したので、範囲ぶん全部を計算する

ここが `uv.lock` の核心です。**あなたが今使っているPythonは、計算に使われません。**

「3.13以上に対応」と宣言した以上、3.13の人も3.14の人も、このロックファイルを使ってインストールします。だからuvは**宣言した範囲の全パターン**について「その人は何を入れるべきか」を先に計算しておきます。

```
requires-python = ">=3.10" と宣言した場合

  3.10 の人 → ?
  3.11 の人 → ?    ← uv がこれを全部計算する
  3.12 の人 → ?
  3.13 の人 → ?
```

手元が3.13でも、3.10用の答えまで計算されます。これをuvは **universal lockfile（万能型ロックファイル）** と呼んでいます。

---

## 3. 答えが変わるところだけ分岐を書く

全パターンを計算しますが、**全パターンを書き出すわけではありません。**

実際に `requires-python = ">=3.10"` で numpy をロックした結果です。

```toml
{ name = "numpy", version = "2.2.6", marker = "python_full_version < '3.11'" },
{ name = "numpy", version = "2.4.6", marker = "python_full_version == '3.11.*'" },
{ name = "numpy", version = "2.5.2", marker = "python_full_version >= '3.12'" },
```

`marker`（条件式）が付いた3行に分かれました。numpyが新しい版で古いPythonのサポートを切っているためです。

注目すべきは3行目です。`>= '3.12'` は3.12・3.13・3.14をまとめて1行にしています。**答えが同じ範囲は1本にまとめる**ので、バージョンの数だけ行が増えることはありません。

分岐が不要なら、`marker` は付きません。同じ `>=3.10` でも sqlalchemy だけを入れた場合、分岐は1つも生成されず、こう書かれただけでした。

```toml
name = "sqlalchemy"
version = "2.0.52"
```

3.10から3.14まで全部これでいい、という意味です。

---

## 4. 分岐の条件はPythonバージョンだけではない

同じ仕組みでOSやCPUも分岐します。このプロジェクトの `uv.lock` にある実例です。

```toml
{ name = "colorama", marker = "sys_platform == 'win32'" },
```

「colorama はWindowsの人だけ」という意味です。あなたのLinux環境では `uv sync` してもインストールされませんが、記述は消えません。Windowsの人が同じファイルを使うためです。

つまり `uv.lock` の分岐は、**Pythonバージョン × OS × CPUアーキテクチャ × Python実装** の組み合わせに対して書かれています。

---

## 5. インストール時に「自分の行」だけが選ばれる

```
uv.lock（全パターンの対応表）
   │
   ▼  uv sync … 今の環境に合う marker の行だけ拾う
.venv（実際に入ったもの）
```

`.python-version` を 3.11 にして `uv sync` を実行したら、実際にこうなりました。

```
Installed 1 package
 + numpy==2.4.6
```

対応表の「3.11の人」の行が選ばれています。3.12以上用の 2.5.2 は入りません。

---

## 6. 保証されるのはどこまでか

uvが保証するのは、**各パッケージが宣言しているバージョン条件に矛盾しない組み合わせ**であることまでです。

3.10用に選ばれた `numpy 2.2.6` を、誰も実行していません。書類の上で条件を満たしているだけです。あなたが3.10で実際に動かして初めて、そのAPIが使えるか分かります。

`requires-python = ">=3.10"` と宣言しても、3.13でしか開発していないなら、3.10で動く保証は実質ありません。宣言は自己申告であり、宣言を広げた分だけ `uv.lock` の分岐は増えますが、動作確認までは付いてきません。

---

## 7. `requires-python` は開発しているバージョンを `>=` で書く

**アプリケーション（自分でデプロイして動かすもの）なら、開発が3.13なら `requires-python = ">=3.13"` と書く。**

> ライブラリを配布する場合は逆で、`>=3.9` のように下を意図的に広げ、CIで各バージョンをテストして裏付ける。以下はアプリの話。

### なぜ下を広げないのか

`>=3.10` と書いても、**uvのバージョン解決は問題なく通ります。** 各ライブラリが3.10対応版を持っていれば、`uv.lock` に3.10用の行が作られ、エラーは一切出ません。

壊れるのは**自分が書いたコード**です。3.13で開発していると、3.10には無いAPIや構文をうっかり使います。それが3.10で実行された瞬間に落ちます。使っていなければ動きますが、3.13でしか動かしていない以上、動く保証はありません。

```
uv の世界（バージョン番号の照合）     自分のコードの世界
  3.10対応のライブラリはある          3.10に無い構文を書いている
  → 解決OK、uv.lock に行が作られる    → 3.10で実行すると落ちる
                    ↑
        uv はこちらを検査できない
```

uvが見ているのはライブラリのバージョン条件だけで、ソースコードの中身は見ていません。確認していない範囲を広げても、増えるのは裏付けのない宣言だけです。

ただし、uvが見ないだけで**リンタは見ます。** ruff に `target-version` を設定して、3.10以降の構文を書いたファイルを検査した結果（ruff 0.16.0）：

```toml
[tool.ruff]
target-version = "py39"
```

```
invalid-syntax: Cannot use `match` statement on Python 3.9 (syntax was added in Python 3.10)
```

一方、`import tomllib`（3.11で追加）は「未使用インポート」としか指摘されませんでした。**構文は拾えるが、標準ライブラリにその版で存在するかまでは拾えない。**

### なぜ上を閉じないのか

下と上ではリスクの大きさが違います。

**下（古いバージョン）は壊れうる。** 3.13で書いた構文が3.10に無ければ、そこで落ちます。

**上（新しいバージョン）は多くの場合動く。** Pythonは後方互換を重視するので、3.13で書いたコードは3.14でもそのまま動くのが普通です。壊れるのは非推奨機能が削除されたときで、削除には数年の予告期間が置かれます（`distutils` は3.10で非推奨、3.12で削除）。

```
         壊れうる            たいてい動く
    ←──────────── 3.13 ────────────→
      3.10  3.11  3.12  ●  3.14  3.15
                     開発中
```

だから上限を開けておきます。アプリで `<3.14` と閉じても得はなく、自分が新しいPythonに上げるたびに書き換える手間が増えるだけです。（ライブラリなら、上限は利用者が新しいPythonへ移るのを止めてしまう。）

ただし「低い」であって「ゼロ」ではありません。新しいPythonが出たら、そのバージョンでテストする必要は変わらずあります。実例として `distutils` は3.12で標準ライブラリから削除されました。

```
$ python3 --version
Python 3.13.13
$ python3 -c "import distutils"
ModuleNotFoundError: No module named 'distutils'
```

### まとめ

```
requires-python = ">=3.13"
                    ↑    ↑
       開発している版    上限は書かない
       （下は広げない）  （将来のPythonを塞がない）
```

`uv init --python 3.13` はこの形を自動で書きます。手で変えるのは、開発に使うPythonを上げたときだけです。
